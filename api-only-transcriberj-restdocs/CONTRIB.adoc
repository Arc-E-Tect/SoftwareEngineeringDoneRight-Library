== Release and CI

This project has independent workflows and release configuration.

* `.github/workflows/api-only-transcriberj-restdocs-build.yml`
* `.github/workflows/api-only-transcriberj-restdocs-release.yml`
* `release.config.js`
* `first-release-patch-analyzer.js`
* `package.json`

Release tags use this module's own scoped namespace (`api-only-transcriberj-restdocs-v*`), independent of the
shared `v*` tag stream used by `sedr-library`. `first-release-patch-analyzer.js` forces the first
real release after the seeded `api-only-transcriberj-restdocs-v0.0.0` baseline tag to compute as `0.0.1`
regardless of the triggering commit's type.

Security scanning does not run from this module's own workflows - it's wired into the shared
`.github/workflows/nvd-cache-refresh.yml` schedule via a `Read-Version-Api-Only-TranscriberJ-RestDocs` /
`Security-Scan-Api-Only-TranscriberJ-RestDocs` job pair, matching the pattern used for `dsl-updater-core`.

== The API-Only TranscriberJ it is built against

The emitter compiles against the TranscriberJ plugin, which carries the emitter interface, and its
tests run the TranscriberJ itself. The plugin is published to the Gradle Plugin Portal from
Arc-E-Tect/SoftwareEngineeringDoneRight-API, at the version `api-only-transcriberj` names in
`gradle/libs.versions.toml`.

While that version is unreleased, it is read from `mavenLocal`, and the CI workflows cannot resolve it.
Release the TranscriberJ first, then set the released version in the catalog and remove `mavenLocal`
from `build.gradle`.
