The Spring Rules project publishes the `architecture-validator-hexagonal-spring-rules` rule pack.
It is consumed by the Architecture Validator plugin as an external rule pack dependency.

== Build

Run from this project directory.

[source,bash]
----
./gradlew clean build
----

== Use in a Consumer Project

Add the rule pack to `testArchitectureImplementation`.

[source,groovy]
----
dependencies {
    testArchitectureImplementation 'com.arc-e-tect.architecture-validator:architecture-validator-hexagonal-spring-rules:<version>'
}
----

The plugin discovers these tests on the classpath and includes them in the generated external rule-pack suite.

== What This Rule Pack Checks

The default rules target Spring-specific architectural boundaries, including dependency direction and domain isolation.

Source test classes include:

* `SpringHexagonalArchitectureTest`
* `DomainIsolationTest`
* `DependencyDirectionTest`
* `PortContractTest`

== Release and CI

* `.github/workflows/spring-rules-build.yml`
* `.github/workflows/spring-rules-release.yml`
* `.github/workflows/spring-rules-security-scan.yml`

Build jobs use configuration cache where compatible.
Publish jobs keep `--no-configuration-cache` for publishing tasks.
