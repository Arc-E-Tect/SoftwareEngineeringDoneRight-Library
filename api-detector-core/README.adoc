== OpenAPI Compatibility

api-detector-core supports OpenAPI v3 documents.
In practice, this means OpenAPI 3.0.x, 3.1.x, and 3.2.x.
OpenAPI v2 (Swagger 2.0) is not supported.
OpenAPI 2 compatibility conversion is explicitly excluded from the runtime classpath.
The library uses `io.swagger.parser.v3:swagger-parser-v3` only.

== Scanning Controllers

`ControllerScanner.scan(Collection<File>)` parses every given file first, so a controller's endpoints include the mappings it inherits from the interfaces it implements and the classes it extends, as Spring MVC serves them.
This is how a controller implementing an interface generated from an OpenAPI contract is written, for example by OpenAPI Generator's Spring generator with `interfaceOnly`:

[source,java]
----
// Generated from the contract, under build/generated/...
@RequestMapping("${openapi.books.base-path:}")
public interface BooksApi {

    String PATH_GET_BOOK = "/v1/books/{id}";

    @RequestMapping(method = RequestMethod.GET, value = BooksApi.PATH_GET_BOOK, produces = { "application/json" })
    ResponseEntity<BookV1> getBook(@PathVariable("id") String id);
}

// Written by hand, under src/main/java/...
@RestController
public class BookController implements BooksApi {

    @Override
    public ResponseEntity<BookV1> getBook(String id) { ... }
}
----

Scanning both files together finds `GET /v1/books/{id}` on `BookController`, at its `getBook` method:

[source,java]
----
List<Endpoint> endpoints = new ControllerScanner().scan(List.of(booksApiFile, bookControllerFile));
----

* A supertype is found among the scanned files through the controller file's imports, its own package, or a fully qualified name; one that is not scanned contributes nothing.
* The controller's own mapping annotations win over inherited ones; otherwise the first supertype that carries one wins, interfaces before the superclass.
* A method the controller does not override, such as an inherited `default` method, is reported at the supertype's file and line.
* A path given as a scanned type's string constant, such as `BooksApi.PATH_GET_BOOK`, resolves to its literal.
* A `${key:default}` placeholder resolves to the property `key` from the `PropertyResolutionContext` passed to `new ControllerScanner(context)`, else to its default; with neither, the value contributes no path.

`scan(File)` scans a single file, and therefore finds no mappings inherited from a supertype declared in another file.

`scan(Collection<File>, Consumer<File> onFileParsed)` scans the same way, and calls `onFileParsed` once per file, in the order given, as soon as that file is parsed, so a caller can drive a determinate progress indicator through what is otherwise one call.
`scan(Collection<File> sourceFiles, Collection<File> controllerFiles, Consumer<File> onFileParsed)` parses both, each file once, but reports only the controllers declared in `controllerFiles`: for scanning one controller whose supertypes may be declared anywhere among the sources.

== Adding the Dependency

The library is published to https://central.sonatype.com/artifact/com.arc-e-tect/api-detector-core[Maven Central].
No repository declaration or authentication is required.

.Gradle (Kotlin DSL)
[source,kotlin]
----
dependencies {
    implementation("com.arc-e-tect:api-detector-core:2.2.0")
}
----

.Gradle (Groovy DSL)
[source,groovy]
----
dependencies {
    implementation 'com.arc-e-tect:api-detector-core:2.2.0'
}
----

.Maven
[source,xml]
----
<dependency>
    <groupId>com.arc-e-tect</groupId>
    <artifactId>api-detector-core</artifactId>
    <version>2.2.0</version>
</dependency>
----

== Who Consumes This

This library is not a Gradle plugin and has no use on its own - it exists to be shared by the
API detector plugin family in the
https://github.com/Arc-E-Tect/SoftwareEngineeringDoneRight-Gradle[SoftwareEngineeringDoneRight-Gradle]
repository: `shadow-api-detector`, `mirage-api-detector`, and `doppelganger-api-detector` (and
transitively, `api-only-suite`, which composes all three). It moved here, and became a real
published artifact, because those plugins previously consumed it as an in-repo
`project(':api-detector-core')` dependency that was never published anywhere public - fine for
building those plugins themselves, but it meant their own published artifacts declared a runtime
dependency on a coordinate nobody could actually resolve.
